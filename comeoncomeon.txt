SOFTWARE ENGINEERING LAB – COMPLETE GIT COMMAND MASTER FILE
==============================================================

Purpose:
This file keeps ALL Git commands collected from Sets 1–8, organized set-wise,
plus a separate section of BASIC & COMMON commands for efficient exam use.

IMPORTANT:
- Replace placeholders such as <repository-url>, <file>, <commit-id>, etc.
- Modern Git syntax uses `git switch` / `git restore`; older papers may accept
  `git checkout` equivalents.
- Do not force-push shared/main branches unless specifically required.
- Set 5, Set 6, and Set 7 contain many repeated command scenarios; they are
  retained set-wise so no question is skipped.


==============================================================
PART A – BASIC & COMMON COMMANDS FOR ALL SETS
==============================================================

A1. Repository setup / clone
----------------------------
git clone <repository-url>
cd <project-folder>

git init
git add .
git commit -m "Initial commit"

git remote -v
git remote add origin <repository-url>
git remote set-url origin <new-url>

A2. Check repository state
--------------------------
git status
git remote -v
git branch
git branch -a

A3. Create and switch branches
------------------------------
git branch <branch-name>
git switch -c <branch-name>
git checkout -b <branch-name>

git switch <branch-name>
git checkout <branch-name>

git branch
git branch -a

git branch -d <branch-name>
git branch -D <branch-name>

A4. Check changes
-----------------
git diff
git diff <file>
git diff main..feature/<name>
git diff main..feature/<name> -- <file>

A5. Stage and commit
--------------------
git add <file>
git add file1 file2
git add .

git commit -m "message"
git log
git log --oneline
git show <commit-id>

A6. Unstage / discard changes
-----------------------------
git restore --staged <file>
git restore --staged .

git restore <file>
git checkout -- <file>

A7. Fetch / pull remote changes
-------------------------------
git fetch origin
git fetch origin main

git pull origin main
git pull --rebase origin main

git log HEAD..origin/main --oneline

A8. Rebase
-----------
git fetch origin
git rebase origin/main
git rebase --continue
git rebase --abort

A9. Reset / revert
------------------
git reset --hard <commit-id>
git reset --soft HEAD~1
git reset --mixed HEAD~1

git revert <commit-id>

A10. Stash
----------
git stash
git stash push -m "unfinished changes"

git stash list
git stash apply
git stash apply stash@{0}
git stash pop
git stash drop stash@{0}
git stash clear

A11. Compare history / branches
-------------------------------
git diff main..feature/<name>
git diff main..feature/<name> -- <file>

git log main..feature/<name> --oneline
git log feature/<name>..main --oneline

git log --oneline --graph --all

A12. Merge
----------
git switch main
git merge feature/<name>
git merge --abort

git push origin main

A13. Push
---------
git push origin <branch-name>
git push -u origin <branch-name>
git push

git fetch origin
git status

git rev-parse HEAD
git rev-parse origin/main

git push --force-with-lease origin <branch-name>

A14. Recover lost commits
-------------------------
git reflog
git switch -c recovery <commit-id>
git reset --hard <commit-id>

A15. Patches
------------
git diff > changes.patch
git apply --check changes.patch
git apply changes.patch
git format-patch <commit-range>
git apply --reject changes.patch

A16. SSH / GitHub
-----------------
ssh-keygen -t ed25519 -C "your-email@example.com"
ssh-keygen -t rsa -b 4096 -C "your-email@example.com"

ssh -T git@github.com

git remote set-url origin git@github.com:username/repository.git
git remote -v
git push origin main

A17. Stop tracking a file but keep it locally
----------------------------------------------
git rm --cached <file>
git add .gitignore
git commit -m "Ignore local configuration file"

A18. Amend the latest commit
----------------------------
git add <forgotten-file>
git commit --amend --no-edit

PART B – SET 1 – HOSPITAL MANAGEMENT SYSTEM (HMS)
==============================================================

GIT
---
1. Initialize repository and first commit:
   git init
   git add .
   git commit -m "Initial commit"

2. Feature workflow:
   git switch -c <feature-branch>
   git add .
   git commit -m "Implement feature"

3. Inspect modifications:
   git status
   git diff

4. Stage changes:
   git add <file>
   git add .

5. Undo a committed change while preserving history:
   git revert <commit-id>

6. Unstage a file:
   git restore --staged <file>

7. Temporarily save unfinished work:
   git stash
   git stash list
   git stash apply

8. Keep clean history while synchronizing:
   git fetch origin
   git rebase origin/main
   git rebase --continue
   git rebase --abort

9. Recover a missing/lost commit:
   git reflog
   git switch -c recovery <commit-id>

10. Configure remote and push:
    git remote add origin <repository-url>
    git push -u origin <branch-name>

MAVEN
-----
Common HMS Maven commands/issues:
mvn -version
mvn validate
mvn clean
mvn compile
mvn package
mvn clean package
mvn test
mvn clean package -DskipTests
mvn dependency:tree
mvn dependency:analyze
mvn help:effective-pom
mvn clean package -X

Key HMS topics:
- Clone/import Maven project.
- If `mvn` is not recognized, configure Maven PATH / JAVA_HOME.
- Check Java/Maven compatibility.
- Resolve dependencies and dependency conflicts through pom.xml.
- Use clean build when stale output causes problems.
- `BUILD SUCCESS` only means Maven build succeeded; the web app can still
  fail to load because of server, port, JSP, WAR, or runtime configuration.
- Missing Maven plugin: verify plugin configuration/repository/network.
- Skip tests when specifically required:
  mvn clean package -DskipTests
- Package/project configuration is controlled through pom.xml.
- Dependency resolution can depend on remote repositories/network and the
  local Maven repository.


DOCKER
------
Dockerfile basics:
FROM <base-image>
WORKDIR /app
COPY <source> <destination>
EXPOSE 8080
CMD ["<command>"]

Build HMS image:
docker build -t hmsapp .
docker run -p 8080:8080 hmsapp

Tag and push:
docker tag hmsapp <dockerhub-username>/hmsapp:latest
docker login
docker push <dockerhub-username>/hmsapp:latest

Useful troubleshooting:
docker ps
docker ps -a
docker logs <container>
docker exec -it <container> /bin/sh
docker stop <container>
docker start <container>

ORS topics:

-----

==============================================================
PART J – HIGH-VALUE EXAM COMMAND DIFFERENCES
==============================================================

1. FETCH vs PULL
----------------
git fetch origin
= Downloads remote updates/references without integrating them into the
  current branch or changing working files.

git pull origin main
= Fetch + integrate remote main, normally by merge.

git pull --rebase origin main
= Fetch + replay local commits on top of remote main.

2. REVERT vs RESET
------------------
git revert <commit-id>
= Safely undo a committed change by creating a NEW commit.
= Preserves history.
Trigger words: "preserve history", "undo faulty commit".

git reset --soft HEAD~1
= Remove last commit, keep changes staged.
Trigger: "undo last commit but keep changes staged".

git reset --hard <commit-id>
= Move branch and working tree to commit; uncommitted changes can be lost.
Trigger: "move branch back", especially when discard is intended.

3. RESTORE vs RESTORE --STAGED
------------------------------
git restore <file>
= Discard working-tree changes in the file.

git restore --staged <file>
= Unstage file but keep working-tree changes.

4. RM --CACHED
--------------
git rm --cached <file>
= Stop tracking file in Git but keep the file locally.

5. STASH
--------
git stash
= Save unfinished changes temporarily.

git stash list
= List stashes.

git stash apply stash@{0}
= Restore stash and keep it in stash list.

git stash pop stash@{0}
= Restore stash and remove it from stash list.

6. REBASE
---------
git rebase origin/main
= Replay feature commits on top of updated main.

git rebase --continue
= Continue after conflict resolution.

git rebase --abort
= Cancel the rebase and return to previous state.

7. MERGE
--------
git switch main
git merge feature/<name>
= Bring feature history into main.

8. REFLOG
---------
git reflog
= Find previous HEAD/branch states and recover commits that appear lost.

9. PATCH
--------
git diff > changes.patch
= Create patch from working-tree differences.

git apply --check changes.patch
= Check whether patch can be applied cleanly.

git apply changes.patch
= Apply patch.

10. FORCE PUSH AFTER REBASE
---------------------------
git push --force-with-lease origin <feature-branch>
= Safer force push after history rewriting.
Use cautiously; avoid on shared main.

11. SAME COMMIT POINT
---------------------
git fetch origin
git rev-parse HEAD
git rev-parse origin/main

If the two hashes are identical, local HEAD and origin/main point to the
same commit.
